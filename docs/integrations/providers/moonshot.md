# Moonshot AI / Kimi (`moonshot`)

**Sourcing note:** `platform.moonshot.ai`/`platform.moonshot.cn`/`platform.kimi.ai` were not directly fetchable from this session's sandbox (egress-blocked). Facts below come from web search corroborated against multiple independent third-party integration sources (GitHub issues from real users hitting real API errors, LiteLLM/OpenRouter/Together provider docs). The **model catalog** is the least reliable part of this research - see below - and is the main reason this provider is rated medium rather than high confidence overall.

- **Platform/domains**: developer docs have migrated over time; current state is `platform.kimi.ai/docs` (international docs), `platform.moonshot.ai` (international console + some guide pages), `platform.moonshot.cn` (mainland China console/docs). API keys are region-locked (a China-issued key only works against the China base URL).
- **Endpoints**: international `https://api.moonshot.ai/v1` (Vader's default); mainland China `https://api.moonshot.cn/v1`.
- **Auth**: `Authorization: Bearer <key>`.
- **OpenAI compatibility**: yes - `/v1/chat/completions` is documented as OpenAI-Chat-Completions-format compatible, drop-in with the official OpenAI SDKs.
- **Streaming**: SSE, OpenAI-style `data: {json}` chunks terminated by a literal `data: [DONE]`; `stream_options: {"include_usage": true}` adds a final usage-only chunk.
- **Tool calling**: modern OpenAI `tools`/`tool_calls` schema (the legacy `functions`/`function_call` shape is explicitly stated as unsupported going forward); multiple/parallel tool calls per turn are supported. A real caveat worth testing against: a Moonshot forum thread reports tool-calling spec-violation edge cases on Kimi K2 that a strict OpenAI-SDK-shaped parser might choke on.
- **Reasoning**: `kimi-k2-thinking` (and K3/K2.7-Code) are reasoning models exposing a `reasoning_content` field, matching Vader's existing convention. A documented requirement: a prior turn's `reasoning_content` must be echoed back verbatim on a tool-call follow-up request or the API may reject it - relevant if Vader's conversation-reconstruction ever needs to special-case this provider.
- **Vision**: `kimi-k3` and the `kimi-k2.5`/`kimi-k2.6`/`kimi-k2.7-code` line are documented multimodal; `kimi-k2-thinking` is not. `modelSupportsVision` matches this exactly. One third-party-sourced (not independently confirmed) claim: Moonshot's vision endpoint may not accept remote/hosted image URLs, only base64 data URIs or a pre-uploaded `ms://<file-id>` reference - worth a live check if image input via URL ever silently fails for this provider.
- **Models implemented, and why the catalog is uncertain**: **updated during the final production-readiness pass's provider re-validation, with live web access this session did not have earlier.** The originally-implemented `kimi-k2-thinking` was confirmed genuinely retired - the whole original kimi-k2 series (including `-thinking`) was discontinued on Moonshot's own direct API on 2026-05-25 ("requests to them no longer succeed" per contemporary reporting); OpenRouter reportedly kept proxying it to third-party hosts for a couple of weeks after, but Vader's `moonshot` provider calls `platform.moonshot.ai`/`platform.kimi.ai` directly, so that grace period doesn't apply here. Replaced with the three models confirmed current as of this pass: `kimi-k3` (flagship, released 2026-07-16, 1M context, multimodal reasoning), `kimi-k2.7-code` (coding-focused, 256K context), `kimi-k2.6` (general-purpose, unchanged from before, 256K context). Given the demonstrated churn, treat this as a snapshot to re-verify against a live account periodically, not a guaranteed-current list; `modelOptionsFallback` lets a user add any newer/renamed model by typing its exact id in Settings without a code change.
- **Context caching**: Moonshot documents automatic context caching with steep (~80-90%) discounted pricing on cache hits, and an optional `cache_id`/`context_id` to bias cache-hit locality across a session - not specially wired into Vader beyond the generic reasoning/usage field plumbing.
- **Not independently verified**: exact current rate-limit tiers and thresholds, and the precise `/v1/models` response schema.
