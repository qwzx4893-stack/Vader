# Alibaba Cloud / Qwen via DashScope (`alibaba`)

**Sourcing note:** `alibabacloud.com`/`help.aliyun.com` were not directly fetchable from this session's sandbox (egress-blocked); facts below come from web search retrieving/quoting those official pages. This is the highest-confidence of the four new providers - DashScope's OpenAI-compatible mode is a long-stable, widely-documented, widely-integrated (LiteLLM, Agno, Promptfoo all support it) surface, not a new or beta feature.

- **Platform**: Alibaba Cloud **Model Studio**, API layer **DashScope** - the official first-party developer platform (distinct from the `qwen.ai` consumer chat app and from third-party re-hosts like OpenRouter).
- **Endpoints**: international/Singapore `https://dashscope-intl.aliyuncs.com/compatible-mode/v1` (Vader's default); mainland China `https://dashscope.aliyuncs.com/compatible-mode/v1`. Newer workspace-dedicated regional hosts also exist (`https://{WorkspaceId}.{region}.maas.aliyuncs.com`) for lower-latency production use - not the default here, but reachable by pasting one into the endpoint field. Keys and models are not portable across regions.
- **Auth**: `Authorization: Bearer <key>`, identical for both native and OpenAI-compatible modes.
- **OpenAI compatibility**: yes, `POST {base}/compatible-mode/v1/chat/completions` is a documented drop-in for the OpenAI SDK. A separate, more-parameter-rich native DashScope endpoint also exists (`/api/v1/services/aigc/text-generation/generation`) but is not used by Vader.
- **Streaming**: SSE, `stream: true`; a real integration report notes DashScope's SSE lines are sometimes `data:{...}` with no space after the colon, which can trip an overly strict parser - worth keeping in mind if streaming ever behaves oddly for this provider specifically.
- **Tool calling**: standard OpenAI schema, with documented native support for multiple/parallel function calls per turn.
- **Reasoning**: thinking-capable models (QwQ, Qwen3.x) accept `enable_thinking`/`thinking_budget` as non-standard `extra_body` params in OpenAI-compat mode (not modeled generically in `alibabaSettings` since they're per-model extras, not a payload Vader's generic reasoning-info plumbing already produces); reasoning output arrives in a separate `reasoning_content` field, matching Vader's existing `nameOfFieldInDelta` convention.
- **Vision**: the Qwen-VL family accepts images via the standard OpenAI content-part array (`image_url`, base64 data URI or hosted URL). `modelSupportsVision` matches any model name containing `-vl`/`vl-`.
- **Models implemented**: `qwen-max`, `qwen-plus`, `qwen-flash` (long-stable, well-documented tiers), `qwq-plus` (reasoning). Newer, more specifically-versioned model IDs mentioned in research (decimal version numbers like "qwen3.8-max") were **not** added to the default catalog since they could not be independently verified against a live model list from this sandbox - add them manually if confirmed current.
- **Prompt caching**: DashScope supports both implicit (automatic) and explicit (`cache_control: {"type": "ephemeral"}`) context caching, minimum 1,024-token cacheable prefix, reported via `usage.prompt_tokens_details.cached_tokens`. Not specially wired into Vader's generic `supportsPromptCaching` detection (which currently keys off `cost.cache_read` being set) - a smaller, separate follow-up if cache-aware cost display for this provider becomes a priority.
- **Not independently verified**: the exact JSON error-body shape (documented error *codes* like `Throttling.RateQuota` were found, but not a confirmed `{code, message, request_id}` schema from a primary source).
